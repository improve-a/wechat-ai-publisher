# EDITORIAL_VISUAL_GRAMMAR V1.0

## 1. 用途与边界

本语法用于把高校官方内容中可复用的编辑规律，转译为 `ArtDirectionPlan` 的受控决策。它不是对任何一个站点、公众号、页面皮肤或视觉资产的复制，也不以机器结果替代人工编辑判断。

固定边界：

- 内容事实、顺序和来源由 `ArticleAST` 约束；
- 图片含义由 `AssetUnderstandingMap` 的 `scene / shotType / subjects / orientation / peopleCount / semanticRoles / relatedSourceBlockIds / visualQuality` 提供；
- `EditorialPlan` 负责内容角色、连续来源分组和资产取舍；
- `ArtDirectionPlan` 只输出受控枚举、资产 ID、来源证据和理由，不输出 CSS、HTML、颜色、像素或任意组件代码；
- Composition Compiler 负责把已验证的语义决策映射到 Registry；
- Renderer 负责微信安全实现；
- 机器只能声明合同和门禁通过，不能声明“达到官方公众号水准”。

## 3. 全局编辑语法

### 3.0 可执行的编排尺度

| 决策 | 建议语法 |
| --- | --- |
| 导语 | 先用一个短段回答“发生了什么 / 为什么值得看”；人物和科研可以略长，图片主导稿应更克制。 |
| section 数量 | 真实长稿通常使用 4–8 个自然内容阶段；按事件语义分节，不按固定字数切块。 |
| 单图 | 适合人物肖像、海报、系统场景、高潮动作或 closing；必须能独立承担新信息。 |
| 双图 | 只在同一场景、连续动作、人物 + 细节或主证据 + 补充证据时使用；默认应有 2/3 + 1/3 或明确的远近关系。 |
| 三图 / grid | 第一张必须是主画面，其余图片补足动作、反应或证据；没有主次时宁可拆开。 |
| 大图与小图 | 大图承担场景、情绪或高潮，小图解释细节；不以等大缩略图追求“整齐”。 |
| 人物照片 | 竖版肖像保留身体姿态，和原话或工作细节建立关系；避免连续重复肖像大卡。 |
| quote | 只在原文确有引语时加入，优先与人物或关键转折绑定，以留白和细线强调。 |
| poster | 独立、居中、只出现一次；不裁成普通横图，也不成为全篇背景模板。 |
| closing image | 优先选择群像、关系完成或与 hero 场景呼应的图片，不能仅因为它位于文件末尾。 |
| section title | 根据稿型选择 rule、eyebrow、numbered、statement、minimal 或 none；内容标签必须有来源证据。 |
| 图注 | 人物 / 演出可 quiet，科研 / 竞赛证据应 metadata，活动稿可 editorial；图注不与正文抢层级。 |
| 留白与密度 | 迎新、人物、演出偏 airy；科研、通知偏 dense；高潮前后应改变停顿长度。 |
| 无卡片 | 普通正文、章节开篇、通栏图、组图、人物叙事、舞台和结尾原则上不需要 card。 |

### 3.1 先决定文章的“观看方式”

`visualTone / density / pace / mediaDominance / textDominance / sectionRhythm` 共同决定阅读方式。它们不直接对应视觉数值：

- `visualTone` 决定语义气质，如 `documentary / humanistic / technical / theatrical`；
- `density` 决定信息应被压紧、平衡或留白；
- `pace` 决定图片转换和段落停顿的速度；
- `mediaDominance` 决定图片还是文字先承担叙事；
- `sectionRhythm` 决定整篇是交替、递进、证据序列还是高潮—释放。

### 3.2 图片必须有角色

每个图片节至少回答以下问题：

1. 哪张是主画面，为什么；
2. 其余图片与主画面是同场景、连续动作、同一人物、证据补充还是对比；
3. 主画面的景别、方向和质量是否适合当前段落；
4. 图片组是否建立了新的信息，而非重复相邻素材；
5. 结尾图片是否回应开场或完成关系收束。

这些决策分别落入 `dominantAssetId / secondaryAssetIds / groupingReason` 和 `WHY_THIS_HERO / WHY_THIS_GROUP / WHY_THIS_DOMINANT_IMAGE / WHY_THIS_CLOSING_IMAGE`。

### 3.3 卡片是少数语义表面

卡片只在内容本身构成独立证据单元时使用，例如指标表或成果聚焦。普通正文、人物叙事、双图、舞台大图、章节开篇和结尾默认保持 flat surface。门禁使用 `CARD_SURFACE_COUNT` 和 `CARD_SURFACE_RATIO` 防止卡片重新成为默认容器。

### 3.4 标签必须有内容证据

章节标签优先从 sidecar 的具体 `scene` 派生，其次使用来源标题。标签必须记录 `labelEvidenceSourceIds`，并拒绝“精彩瞬间”“现场与过程”“活动现场”“更多内容”等泛化词。

## 4. 按文体区分的视觉语法

### 迎新

- 图像主导、节奏动态但密度舒展；
- 校园宽景建立尺度，服务点以同场景双图推进；
- 结尾优先新生 / 志愿者群像；
- 典型组合：`hero-visual → asymmetric-photo-pair × N → full-width-story → closing-visual`。

### 竞赛

- 倒计时或阶段序列建立紧张感；
- 调试中景与技术细节成组，关键动作使用 `visual-climax`；
- 指标属于证据，不应铺满全文；
- 奖杯之后仍需团队、复盘或长期价值完成收束。

### 人物获奖

- 以肖像建立观看关系，工作现场和物件细节证明人物；
- 引语形成安静停顿，不依赖厚重引语卡；
- 颁奖照只是时间节点，不能压过长期工作；
- 结尾从个人移动到团队或传承关系。

### 演出

- 舞台横图和人物竖图形成方向对比；
- 图像承担高潮，文字保持克制；
- 海报只作为一次识别节点，不在每节复用；
- 谢幕之后保留“释放—余韵”的收静段。

### 科研成果

- 从假设、方法、验证、边界到复核形成证据链；
- 图注采用 metadata 取向，表格只承载关键指标；
- 大图先建立系统场景，小图补充波形、样件或限制条件；
- 结尾强调开放验证或下一步，而非装饰性荣誉面板。

### 社会实践 / 活动回顾

- 以地点、人物、行动或路线构建纪录片式连续性；
- 肖像必须保留尊重的观看距离；
- 成果回到现场和参与者，不用数字卡替代过程；
- 开场与结尾应形成地点、问题或关系上的回声。

## 5. 微信安全实现语法

- 不依赖媒体查询或 CSS Grid 才能成立；
- 非对称双图使用 inline-block 百分比宽度，失去高级布局能力时仍保持来源顺序；
- 图片始终 `max-width:100%`、高度自适应；
- 所有样式继续通过 allowlist，禁止脚本、外部样式和危险 URL；
- 375px 浏览器门禁检查文档、文章和所有元素的横向溢出。

## 6. 机器与人工分工

机器验收：来源完整性、schema、序列化、确定性、Composition 兼容、微信 HTML、安全宽度、资产加载、卡片比例、标签泛化率、文章间序列相似度。

人工验收：信息层级、图文节奏、视觉主次、大图运用、组图叙事、人物 / 场景适配、标题设计、段落转换、模板感控制、整体公众号完成度。
